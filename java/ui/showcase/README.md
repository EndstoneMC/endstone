## Contents

| Path | What it is |
| --- | --- |
| `generate.py` | Builds `pack/` and `build/zernyth_ui_showcase.mcpack` (textures, JSON UI, manifest) |
| `validate.py` | Static checks. Usage: `python validate.py <folder with the vanilla ui/*.json>` |
| `preview.html` | Browser approximation built from the pack textures (serve the folder, e.g. `python -m http.server`) |
| `plugin.yml` | Metadata for the test plugin JAR |
| `markers.json` | Title and button markers shared by the pack and the plugin |
| `../src/example/java/.../UiShowcasePlugin.java` | Test plugin with `/zuitest` |

Build the plugin from `java/`:

```
gradlew -p . :ui:showcasePluginJar
```

This writes `ui/build/showcase/zernyth-ui-showcase.jar`.

## How it works

- Every screen is a normal **action form** from the engine (`ZernythUI` builder).
- The title starts with an invisible marker made of colour codes followed by `§r`, for example `§1§2§3§a§r` for the main menu.
- The pack replaces the factory in `server_form.main_screen_content`:
  - Without a marker, the vanilla form is shown, so other plugins are unaffected.
  - With a marker, the matching Zernyth layout is shown.
- Buttons stay real form buttons (`button.form_button_click`), so the engine receives the same button index as always.
- Button text markers:
  - `§9§8§r` marks information cards (right column of the god detail).
  - `§9§7§r` marks shop category tabs.

| `/zuitest …` | Layout |
| --- | --- |
| `main` | 3 × 2 image tiles with icon, title and description |
| `teams` | 3 × 3 image tiles with text at the top |
| `gods` | Scoreboard text on the left, scrolling grid of god cards on the right |
| `god` | Banner, description with Yes/No, two information cards |
| `stats` | Scrolling text and a Back button |
| `shop` | Category tabs on the left, item cards with buy and sell prices |

## Installing on a test server

1. Copy the content of `pack/` (or unpack the `.mcpack`) to `<bds>/resource_packs/zernyth_ui_showcase/`.
2. Add the pack to `<bds>/worlds/<world>/world_resource_packs.json`:
   ```json
   [{ "pack_id": "6f1c2a8e-4b7d-4e2a-9c3f-2d8b5e7a1c40", "version": [1, 0, 0] }]
   ```
3. Set `texturepack-required=true` in `server.properties`. Without the pack, players see normal forms.
4. Copy `zernyth-ui-showcase.jar` into the `plugins` folder of the Zernyth Engine server and start the server.
5. In the game, run `/zuitest`, `/zuitest teams`, `/zuitest gods`, `/zuitest god`, `/zuitest stats` and `/zuitest shop`. This needs the permission `zernyth.ui.test`, or operator.

### Testing the HUD

The Zernyth Java API has no scoreboard or actionbar functions, so the plugin cannot drive the HUD. Use vanilla commands instead:

```
/scoreboard objectives add zstats dummy "YOUR STATS"
/scoreboard objectives setdisplay sidebar zstats
/scoreboard players set Money zstats 567
/scoreboard players set Kills zstats 0
/title @s actionbar PvP: §aON   §aIn spawn
```

## What to check and report

Record the client version and platform (Windows, Android, iOS, console), then check:

- [ ] Each `/zuitest` screen shows the Zernyth layout instead of the vanilla form.
- [ ] Buttons react to clicks and taps, and hover and press states change.
- [ ] Navigation works (main → shop/gods/teams/stats, Back).
- [ ] The close button (×) closes the form.
- [ ] Tile images come from the pack. Colour codes in texts work; the title markers stay invisible.
- [ ] The god detail shows only Yes/No in the middle and the two LVL cards on the right.
- [ ] The shop shows only items in the grid and the three tabs on the left.
- [ ] Scrolling works in the god list, the shop and the stats screen.
- [ ] The HUD sidebar shows the frame and ribbon with the objective name, and the actionbar shows the frame.
- [ ] Forms from other plugins (title without marker) still look like vanilla.

## Known risks

- **Not checked against a client:**
  - `#title_text` string subtraction, grids with `#form_button_contents` → `#maximum_grid_items`, and hiding grid cells through `#visible`. These follow the vanilla files and common practice.
  - That `server_form.json`, `scoreboards.json` and `hud_screen.json` in the pack replace the vanilla definitions property by property.
- Other packs that also change `server_form.json` or the sidebar can conflict with this one.
- The window has a fixed size of 340 × 226 GUI units and may be too large on very small screens with a large GUI scale.
- After each Minecraft update, re-run `validate.py` against that version's vanilla files. The element names may change.
- `markers.json` and the constants in `UiShowcasePlugin` must match; `validate.py` checks this.
